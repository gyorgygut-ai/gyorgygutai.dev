# CV Review Checklist — Software Developer

Run through this before every application. Copy-paste relevant items into a per-application note if needed.

---

## 📐 Format & ATS

- [ ] Single-column layout — no tables, text boxes, sidebars, or multi-column tricks
- [ ] Standard section headers: `Experience`, `Skills`, `Education`, `Projects` — no creative names
- [ ] One font, body 10–11pt (Calibri, Arial, Inter, Helvetica)
- [ ] No icons, photos, charts, skill bars, or color blocks
- [ ] Standard bullet characters (`•` or `-`), no fancy symbols
- [ ] File named `firstname-lastname-resume.pdf` — not `Resume_v3_FINAL.pdf`
- [ ] PDF by default; .docx only if the ATS explicitly requests it
- [ ] Date format consistent: `Jan 2023 – Present` or `2023 – Present`

---

## 🔗 Links & Contact

- [ ] GitHub URL in header, written out as full URL (not hidden behind anchor text)
- [ ] GitHub profile is populated — pinned repos are real, recent, and not empty forks
- [ ] LinkedIn URL in header, written out as full URL
- [ ] LinkedIn profile titles and dates match the CV exactly
- [ ] Professional email (firstname.lastname@...)
- [ ] City + country listed (not full address)
- [ ] No broken links — click every URL before sending

---

## 💬 Header & Summary

- [ ] Top third of the CV carries the most weight — lead with your strongest signal there
- [ ] No "Objective" statement — the job you're applying to is your objective
- [ ] Summary (if included) is 2–3 sentences: role + specialty + biggest shipped thing
- [ ] No "References available upon request" — implied, wastes a line

---

## 🛠 Skills Section

- [ ] Grouped by category: Languages, Frameworks, Infrastructure, Databases, Tools
- [ ] 12–18 skills listed — no more, no less
- [ ] Every must-have technology from the JD appears in this section
- [ ] Both full name and abbreviation included where relevant: `Kubernetes (K8s)`, `Amazon Web Services (AWS)`
- [ ] No self-rated bars (`Python ★★★★☆`) — universally mocked, not parseable
- [ ] No outdated technologies you no longer want to work with (jQuery, Flash, ColdFusion)
- [ ] Skills are corroborated by experience bullets — unsupported laundry lists = keyword stuffing

---

## 📊 Experience Bullets

- [ ] Reverse chronological order — most recent role first
- [ ] 3–6 bullets per role (more for recent, fewer for older)
- [ ] Each bullet follows: `[Action verb] + [what you built/did] + [technology] + [quantified result]`
- [ ] At least 60% of bullets have a number (latency, scale, cost, %, RPS, users)
- [ ] Top 3 bullets in most recent role address the top 3 JD requirements
- [ ] Engineer-specific quantification: latency/throughput, cost savings, reliability (SLO), scale (RPS/events), team impact
- [ ] Bullets describe *your* work, not the team's — "Implemented X" not "Our team launched X"
- [ ] No vague soft-skill bullets: "Strong communicator," "Team player," "Detail-oriented"

---

## 📏 Length & Structure

- [ ] 1 page through senior level (≤8 years experience)
- [ ] 2 pages from staff/principal level with genuine substance to fill them
- [ ] If second page has only 4 lines, condense to one
- [ ] Education at the bottom past second job; at the top for new grads
- [ ] GPA only if 3.5+ and you're a new grad — drop after first job

---

## 🔍 Per-Application Tailoring

- [ ] Match-check: 75%+ keyword match against the specific JD
- [ ] Swap in 1–2 keyword-aligned bullets if there's a substantial mismatch
- [ ] Skills section reordered to match JD priority (JD says "Rust" first → Rust goes first)
- [ ] For dream roles: lead with the bullet mapping closest to the JD's primary need

---

## 🚫 Red Flags to Remove

- [ ] "Objective" or "Career Summary" written in third person
- [ ] Photos (US/intl tech convention: no)
- [ ] Hobbies (unless competitive athletics, published work, or OSS with real traction)
- [ ] Generic soft-skills sections
- [ ] "Tech Stack" or "Engineering Toolkit" as section headers (use "Skills")
- [ ] Keyword-stuffed skill lists that don't appear anywhere else in the CV
- [ ] Perfectly templated bullets with no numbers or specifics

---

## ✅ The 5-Second Test

Hand your CV to someone. Count to 5. Take it back. Ask:
1. What is my current role?
2. What is my strongest technical skill?
3. What is one metric I achieved?

If they can't answer all three, rewrite.
